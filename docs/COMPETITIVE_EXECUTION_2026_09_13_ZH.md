# PaperPath：面向领先体验的执行计划

日期：2026-09-13。状态：本轮九项清单完成。本计划接续同日文档工作台迭代。

## 目标与比较口径

目标是在本地 PDF 完成任务上建立可重复验证的优势，而不是宣称全功能超过所有厂商。
竞品官方来源与平台边界沿用 [同日竞品复核](PRODUCT_ITERATION_2026_09_13_ZH.md)：
Apple Preview、Acrobat Mobile、PDF Expert、PDFgear、Xodo、Foxit、iLovePDF。
没有安装并计时全部竞品，因此本轮不能给出速度排名、质量排名或“业界第一”认证。

| 对标压力 | PaperPath 要兑现的标准 | 本轮范围 |
| --- | --- | --- |
| Preview / PDFgear 已具备大量基础能力 | 重复处理与中断后继续，应比重新找文件、重新跑任务省事 | OCR 页级恢复 |
| PDF Expert 的文档中心体验 | 文件、问题页、输出副本之间能直接跳转 | 批量结果可打开实际产物，真实缩略图服从隐私设置 |
| Xodo 的专业批量工具 | 每份结果清楚，失败不能被整体成功掩盖 | 所有待复核项进入人工流程，包括没有页码的检查失败 |
| Acrobat / Foxit 的可信度与深度 | 明确检查范围，保持原件与已提交结果 | 不把未知算通过，结果持久化失败可见，已完成批次可重找 |
| iLovePDF 的短任务路径 | 无需从头跑一遍或重复生成已完成副本 | 批量重试保留成功结果，OCR 恢复按源修订与参数精确匹配 |

## 执行清单

各项顺序实施，遇到缺陷就修正，不等待中途确认。所有完成状态必须有代码或运行证据。

| 轮次 | 工作 | 验收 | 状态 |
| --- | --- | --- | --- |
| R1 | OCR 检查点合同：源修订、参数、页数、算法版本 | 不同修订/语言/词表/版本拒绝复用；不得把部分结果当完成索引 | 完成，失效诊断通过 |
| R2 | OCR 每页受保护原子保存，继续时跳过已完成页 | 中断后重新打开存储并恢复；损坏页单独重算，不重写全部累计文字 | 完成，中断/损坏恢复通过 |
| R3 | OCR 入口展示已保存页数，执行进度衔接 | 同参数显示可继续；改参数立即失效；完整结果原子保存后清检查点 | 完成，参数切换实测和正式索引提交通过 |
| R4 | 批量预检保守分类 | blocked 优先；任何 review 均不得自动进入创建，包括无页码项 | 完成，九组边界和混合批次通过 |
| R5 | 批量持久结果与并发边界 | 全部完成后仍保留最新批次；记录保存错误可见；避免两个批次互相覆盖 | 完成，恢复/复用/保存失败/时间迁移通过 |
| R6 | 批量结果工作流 | 结果直达输出；问题优先排序；隐藏预览时不生成真实页面 | 完成，产物直达和隐藏预览实测通过 |
| R7 | 有限行为检查与真实产物诊断 | 覆盖断点、复用、失效、损坏、原件不变；记录实际观测而非估计 | 完成，最终两台模拟器各五条通过 |
| R8 | 构建与模拟器体验修正 | 主 App / Share Extension 编译；iPhone / iPad 实拍和关键操作 | 完成，七轮构建通过，明暗与 OCR 恢复实拍 |
| R9 | 交付与后续差距更新 | 完整迭代记录、证据、优先级及未验证边界；本轮清单闭环 | 完成，见本文与证据索引 |

## 工程约束

- 保留所有既有未提交更改、调试文件、历史记录；不提交或推送。
- 使用现有 PDFKit / Vision、存储保护和原子提交，不引入在线 OCR、账号或新付费依赖。
- OCR 恢复数据与正式分析分离，只保存完成页；进程终止不会把半份结果标成全文识别完成。
- 恢复匹配包含修订和配置；记录已变更、删除或锁定时拒绝旧写入。
- 结果、异常与停止保持可见，不以短暂通知替代持久状态。
- 新交互继续使用已有语义色、SF Symbols 和命名动效，响应 Dynamic Type 与 Reduce Motion。

## 行业领先仍需的外部证据

本轮可以实现上述工程目标，不能在当前环境内证明整个 PDF 市场的第一名。
后续发布门槛仍包括同机同样本竞品操作计时、真实用户完成率与留存、
长文档真机内存/能耗、复杂 Office 互操作、相机/Pencil/锁屏、故障注入及购买恢复。
任意内容流编辑、XFA 和证书签名需独立评估成熟引擎，不能用更多启发式规则承诺通用支持。

## 实施记录

### OCR 恢复

- `VisionOCRService` 新增检查点输入和逐页完成回调，复用 Vision 识别与已有识别质量策略，没有增加云端处理。
- `OCRCheckpointIdentity` 绑定文档 ID、内容修订、页数、规范化语言/词表、识别规则版本和系统版本。
- `DocumentStore` 在 `OCR/<record-id>.resume/` 保存身份与独立页面 JSON。完成页用既有受保护写入、指纹复核与原子替换发布，避免每识别一页重写全部累计文本。
- 单页编码上限 8 MiB，加载总量上限 128 MiB，继续执行既有 1,000 页、10 万文字块和 64 MiB 文字预算。这些是拒绝超量输入的预算，不是“峰值内存只有这些”的测量。
- 缺失或损坏的页面只重算该页；不把部分恢复结果发布成完整 OCR 索引。文档变更、删除清理沿用 sidecar 生命周期。
- 正式 OCR 结果经原子分析提交成功后清理检查点；保存失败时不会先删除恢复数据。清理失败最多留下不可用于其他修订的冗余缓存，不删除正式结果。
- 配置页改为真实文件预览、名称与元数据，删除重复统计头部。显示保存页数及“继续识别”；参数变化后不显示不匹配进度。
- 已验证中断一页后重建存储实例，继续仅计算第 2、3 页；损坏第 2 页 JSON 后，仅重算第 2 页；源 PDF 指纹不变。
- 补充生产入口验证：三页识别结果提交到正式索引后，检查点目录被移除。

### 批量交付

- `batchAttentionItem` 统一分类：阻止项优先，任意待复核项均进入复核；即使没有问题页码，也不会自动创建输出。整体状态为 review/blocked 而明细不完整时仍保守处理。
- 新增批次运行所有权，UI 从保存初始状态到终态持久化期间独占；同一模型内第二批次被拒绝，不改动文档原有互斥。
- 完成批次不再因“没有待恢复项”在启动时删除。`currentBatchDeliveryRun` 与 `recoverableBatchDeliveryRun` 分工明确，最新完成结果仍可找回。
- 恢复时先寻找已持久化输出，再把非终态视为停止，覆盖提交完成但 UI 状态尚未更新的时窗。
- 保存结果返回明确布尔值，UI 保留错误和重试保存按钮。初始恢复记录保存失败不会启动批量输出。已提交 PDF 独立保留在成果中。
- 延迟保存携带创建时的快照时间，拒绝更早批次/快照。停止时最终保存由独立任务完成，不继承工作任务的取消。
- 列表优先显示问题；已验证行可直接打开实际输出，继续绑定输出修订。列表和问题详情都遵守隐藏预览。
- 删去重复指标头部，保留一组处理计数；修复相关动态文案和旧记录中文显示。状态标记使用语义色描边，避免深色亮底上的白色图标低对比。
- 混合批次真实执行结果：1 份可交付输出，1 份未完成表单待复核，1 份无页码的不完整检查待复核。最后一项通过受控缓存注入构造，不是现场识别了一份超大表单。
- 重建模型后结果仍在，重试复用已完成副本，文档数量不增加。完整成功批次也能重新加载。

### 实际发现并修复的问题

第二轮扩展诊断在 iPhone 通过、iPad 失败，失败点是旧快照覆盖已完成批次。
原因：共享 JSON 编码器以 ISO-8601 秒精度保存时间，同一秒内多个批次的先后关系在重读后丢失。

修正仅作用于批次状态：新写入使用保留小数的 epoch 秒；读取先尝试新格式，再兼容旧 ISO-8601。
不整体修改资料库时间格式。新增精度往返、旧格式读取和过期快照拒绝诊断，两台均通过。
旧失败报告留在证据目录，不删除以营造“所有轮次均无问题”的印象。

第六轮复跑又暴露同批次开始时间往返后存在浮点舍入差，合法快照在进入保存前被拒绝，
并非磁盘旧结果被删除。独立 1,000 次 Date 编解码实验复现其中 254 次读回略晚。
最终同批次使用当前记录的开始时间，只比较快照时间；跨批次才比较开始时间。
新增人为一微秒偏差验证，最终两台均通过，并拆分诊断断言避免混淆失败原因。

保存失败使用结构超限快照触发真实存储拒绝，确认上一份磁盘记录保持不变，错误进入发布状态，
重试成功后清除。它不是磁盘耗尽或掉电试验，不能据此宣称所有故障注入已通过。

## 后续优先级

这不是额外承诺本轮已经完成的任务，而是达到行业领先仍缺的证据与能力：

1. P0：低存储、系统终止、锁屏与跨窗口长任务的真机故障矩阵；发布前保护已提交结果。
2. P1：固定设备和真实样本上的竞品对照，包括完成时间、误交付率、恢复时间、峰值内存；先建立数据，再宣称领先。
3. P1：复杂 Office/iWork 打开、打印、版式与关键字段保留；当前结构导出不等于通用高保真编辑。
4. P1：OCR 恢复存储在千文件库、千页文档下的 I/O 与峰值内存；当前逐页写入会重读资料库索引，未测大库成本。
5. P1：目标用户任务完成率、二次使用与付费；本地闭环优势仍需用户验证。
6. P2：复杂内容流、XFA、数字证书签名，先评估成熟引擎、授权成本与离线边界。
