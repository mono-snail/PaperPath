# PaperPath V48：字符修订证据、条码页面锚点与版本归档核验

## 本轮目标

V47 已完成词句级差异、Receipt 与里程碑双向导航、扫描替换复核及固定版本容量治理。V48 不重复这些能力，继续收敛三个有代码证据的断点：

- 短词、编号和金额只显示整词变化，无法突出具体字符。
- 无文字重复模板缺少页码文本之外的稳定身份。
- 里程碑 ZIP 可以导出，但重新选择后无法证明清单与 PDF 字节仍一致。

本轮定位：**在不写入 PDF、不解压外部内容、不新增网络路径的前提下，把修订证据和离线归档完整性提升到更精确、可解释、可重新核验的层级。**

## 核心变化

### 字符级修订证据

- 同位置替换词优先定位到具体组合字符。
- 字符证据与词级回退拥有不同视觉语义。
- 每页词元、字符、红线数量均有硬上限。
- 页面变化项同时展示严重度、证据粒度和配对依据。

### 无文字模板锚点

- 低文本页面可从二维码、Aztec、Data Matrix、PDF417 和 Code 128 获取本机锚点。
- 原始条码负载不进入 Receipt，仅保留有界 SHA-256。
- 重复条码自动失去唯一锚点资格，不覆盖既有单调配对保护。

### 版本归档核验

- 新归档清单升级为 `PaperPath Version Archive V48`，同时兼容 V47。
- 存储中心可选择已导出的 ZIP 进行只读重新核验。
- 核验覆盖 ZIP 结构、中央目录、本地头、CRC、PDF 头、字节数和 SHA-256。
- 核验不解压 PDF、不导入资料库、不写回外部归档。
- 报告明确表示内部一致性，不宣称签署者身份或法律认证。

## 竞争优势

- 文本层修订可从整词进一步收敛到具体字符中段，同时保留可靠回退。
- 无文字模板页可使用条码身份参与本机单调配对，原始负载不持久化。
- 版本归档离开 App 后仍可重新核验每个 PDF 的清单、CRC、字节数与 SHA-256。
- 核验过程只读、流式、本机执行，不生成解压副本或网络上传路径。

## 未验证风险

- PDFKit 对连字、竖排、双向文本和异常字体的单字符选择精度仍需真实样本验证。
- 160pt 比较缩略图上的小型或低对比度条码可能无法被 Vision 识别。
- 条码检测的真机能耗和长文档耗时仅受代码预算约束，尚未实测。
- ZIP 核验仅支持 PaperPath 生成的 STORE-only、无注释、非 ZIP64 归档，不是通用解压器。
- 核验证明归档内部与清单一致，不证明清单来源身份；数字签名仍不在当前能力边界。
- Files/iCloud Provider 上的大归档下载、取消与文件协调尚未真机验证。
