# 原生文档工作台：视觉与交互迭代

范围：资料库、阅读页、成果列表和转换结果。目标是专业、统一、文档优先，
减少长页面、重复说明和装饰性信息，不修改已验证的转换、安全和存储合同。

## 六轮执行计划

| 轮次 | 范围 | 验收标准 |
| --- | --- | --- |
| 1 | 字体、色彩职责、工具控件 | 品牌保留识别度，文件及操作采用统一系统字体；不增加装饰性色彩 |
| 2 | 资料库 | 首屏文件更突出；减少重复入口；iPad 利用现有分栏放大真实预览 |
| 3 | 阅读页 | 阅读状态缩减常驻工具，编辑模式可切换；恢复、识别和风险信息仍可访问 |
| 4 | 成果列表 | 文件行、预览、来源、状态和操作布局统一；重要异常不以颜色单独表达 |
| 5 | 转换结果 | 实际输出预览与文件信息优先；未保留内容始终可见，长解释按需展开 |
| 6 | 验收修正 | 手机/iPad、明暗主题、辅助字号；阅读切换和历史成果检查真实点击通过 |

## 设计约束

- 使用现有 SwiftUI 导航、菜单、分组与 SF Symbols；不把 iOS 界面改成 Web 风格组件。
- 字体角色采用系统动态字号；品牌可保留衬线，文件名和工具标题不使用衬线装饰。
- 颜色分工：中性表面、品牌强调、语义警示；不增加彩色竖线或渐变装饰。
- 文档缩略图来自实际 PDF，Office 预览来自实际输出；隐藏预览设置必须贯穿新预览。
- 关键提示不移除；解释可折叠，但未保留内容、受影响页数和保存失败始终可见。
- 所有新异步预览绑定文件/修订，取消、后台和保护数据不可用时清理，不能泄漏旧结果。
- 不修改 Office 算法、OCR 检查点、批次选择语义、权限、付费或版本号。
- 仅紧凑工具条局部约束字号，正文和文件名支持辅助字号换行。
- 不重置用户已有的工具名称、密度和预览偏好；减少动效时保持可用。

## 实际改动

### 第 1 轮：视觉规范

新增 `PPType` 的区块、文件名、元信息、数值角色，采用系统动态字号；
品牌字样保留衬线。顶层导航采用同一品牌强调色，动作与异常的色彩职责分开。
移除这条主路径中重复的彩色缩略图下划线、阅读页角标和成果行侧边装饰。

### 第 2 轮：资料库

去掉品牌/搜索下方重复的页面标题和导入按钮组，保留导航栏导入、扫描和创建入口。
文件名、页数和文件大小优先，减少摘要段落；真实缩略图与文件类型占位保持稳定尺寸。
平板分栏从 820pt 起启用，预览栏随空间在 320–480pt 之间调整，
预览宽度从 192pt 增加至 252pt。不重置用户原有列表、网格、密度或隐藏预览偏好。
分栏下不再重复显示“继续处理”的同一批文件。

### 第 3 轮：阅读页

阅读模式移除重复分类/说明条，相关 OCR 或风险信号仍可直接访问。
底部保留页码导航和一条操作栏：模式切换、查找、阅读选项、专注阅读。
批注、页面、交付模式仍保留各自工具；工具名称设置仍保存。
进入/退出专注阅读不改变页码，保留系统导航和减少动态效果支持。

### 第 4 轮：成果列表

PDF 与 Office 文件行采用统一字体层级和大小稳定的文件图示；
来源名称、文件大小及需核对状态各自有明确位置。
PDF 文件打开、检查记录和分享是独立动作，普通字号横向排布，辅助字号自动转纵向。
低频创建和核验入口保留在“更多操作”，不再以整块功能介绍占据成果页。

### 第 5 轮：转换结果

先显示输出文件、格式、大小和系统 Quick Look 实际内容预览。
未保留图表/图片、无文字页、需核对表格位置等摘要始终可见，
长解释及精确源页码使用原生 DisclosureGroup 展开，完整检查页继续保留。
不把“已保存”当成“内容完整”；失效/缺失记录显示实际可用性。
文件信息区仅局部限制最大字号，限制说明正文仍按辅助字号放大。

预览通过已有受保护副本准备 API 获取实际输出，不用源 PDF 假冒转换结果。
自动预览限制为 32 MiB；超出时保留手动预览入口。请求绑定输出 ID 和源修订，
后台、保护数据不可用、隐藏预览或离开时移除内容及临时副本；
返回前台可重新准备，生成失败保留明确状态和重试按钮。
系统 Quick Look 的视觉加载与文件准备分开验收，不能仅凭准备 API 返回就声称图像已显示。

### 第 6 轮：实拍修正

- 最初系统缩略图服务没有为 Excel 返回图片，改为复用已有 Quick Look 控制器；
  原失败截图保留，不用空框当作完成。
- 修复阅读模式菜单标识覆盖、DisclosureGroup 父容器覆盖子内容的问题。
- 辅助字号下收紧文件状态及元信息，文件名允许换行，正文不全局缩小。
- 预览工具行固定图标尺寸及 44pt 命中区域；已保存结果的预览/分享/重做保持单行，
  不让辅助字号把底部工具区扩成三层。未保存结果的重试保存仍支持纵向布局。
- 增加真实表格像素检查，避免把 Quick Look 载入动画截成最终成果。
- 运行时定位 iPad 搜索后打开结果再切后台的点击失效：
  后台清空搜索文本时未结束系统搜索呈现。同步设置 `isLibrarySearchPresented = false`。
  不经搜索对照通过、原搜索路径失败、修复后原路径通过，证据见调试记录。
  撤回无效的 Quick Look 容器和后台保留控制器尝试，保留严格副本清理。
- 中文普通/最大字号资料库和阅读页、中文结果预览均进入 UI 回归。
- PDF 成果使用真实核验副本生成后重开，检查列表行的独立记录入口；
  修正旧自动化依赖的已移除入口文案。最终从资料库进入阅读及交付，双设备通过。

完整日志、最终截图及各轮结果见
[验收证据](../design/native-workbench-2026-09-15/README.md)。
语料使用前轮公开文件在生产路径导出并保存，没有伪造成功记录。
UI 调整不等于新增 Office 保真能力，不更改上一轮关于公式、图表、SmartArt 和跨应用编辑的边界。
本轮没有执行代码提交、版本更改、推送或提审。
没有执行真机 Pencil/多窗口压力测试或完整 XCTest 套件；旧单测接口编译问题仍单独处理。
自动化验收不能代替真实用户研究，不据此宣称设计或功能达到行业第一。

结果：六轮实施完成；手机完整六项通过，平板五项主界面与独立 PDF 成果路径通过。

保留失败日志并列为发版前专项复查项，不将该路径算作通过。
