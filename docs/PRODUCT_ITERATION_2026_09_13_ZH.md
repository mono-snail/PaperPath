# PaperPath：竞品复核与文档工作台迭代

日期：2026-09-13。对象：现有 SwiftUI iPhone / iPad App，不是 Web 重写。

## 1. 结论

**定位：不依赖账号的本地 PDF 完成工具。拿到文件，整理或签批，检查副本，再交付。**

“功能多”“免费”“离线”“原生界面”都不是独占优势。系统预览和免费工具已经把基础能力的门槛抬高。PaperPath 值得投入的组合是：

1. 文件和真实页面始终是界面中心，少找工具，少丢上下文。
2. 明确区分工作副本、输出副本和历史版本，不把旧检查用于新文件。
3. 交付前列出具体问题，交付后保存检查结果；用户能找回自己究竟发了哪一份。
4. 不强制注册，不把普通文档处理引到在线服务，付费边界符合本地工具心智。

这是一项产品假设，不是市场验证结果。不能从代码规模、截图或竞品宣传得出“用户一定愿意下载/付费”。

## 4. 本轮迭代记录

### R1：复核产品方向

- 对比七类直接或替代工具，增加 iOS 26 系统 Preview 作为基础门槛。
- [旧核心路线](CORE_DIRECTIONS_ROADMAP_ZH.md) 标为历史基线并链接本次复核；其中“竞品多数只有工具、离线是独有优势”等表述不再作为当前判断。
- 选择“可看清的文档完成与交付”作为本轮切入点，不扩大到服务端或 AI 聊天。

### R2：有界真实页面缩略带

- 新增共用 `PDFPageFilmstrip`；点缩略图、前后页、指定页码是同一页选择状态。
- 附近最多九页参与视图构建，万页文件不会先生成万张缩略图。
- 复用现有异步缓存、源修订、保护数据和后台清理逻辑，不另建 PDF 解码器。
- 选中态同时有描边和无障碍 selected trait，不仅依赖颜色。
- 页码导航保留 44pt 命中区域，滚动过渡服从 Reduce Motion。

### R3：iPad 文档预览

- 预览增加中性托底，让白色纸页与工作区分离；真实内容不染色。
- 用页面缩略带替换原来的纯页码行，按页检查不必先进入阅读器。
- 页面选择回写继续绑定文档修订，不改用户原文件或阅读器实例。
- 常用动作双列排列，保留全部工具、交付入口和结果回执。

### R4：发送前先看文件

- `DocumentExportSheet` 的安全交付头部换为真实页、文件名、页数/大小、工作副本/已验证副本。
- 点页面可进入现有阅读器检查；沿用现有异步检查点和修订约束。
- 指定页码拒绝越界输入；源修订变化时关闭页码选择并复位。
- 隐藏预览开启时不生成缩略图，锁定文档不泄露页内容。
- 大字号优先文件名和可访问的预览按钮，不强迫文字挤在小图旁。

### R5：检查结果可扫描

- 明确显示各类检查项的实际数量：通过、自动修复、待复核、阻止输出。
- 数量来源于当前修订的真实检查项，不生成“安全分数”或装饰性进度。
- 检查详情、停止、重试、阻止输出和已有结果持久化机制继续保留。

### R6：手机和工具目标

- 手机导入/扫描/新建按钮与标题同行，保留可访问名称、悬停说明和触控目标。
- 普通文件缩略图由 40pt 增至 48pt，继续工作条目由 44pt 增至 56pt。
- 文档缩略图下沿用类型色作辅助标识；高置信分类可显示文字标签，空间不足回退到页数/大小。
- 工具目录的目标文件改为真实缩略图、文件名与元数据，不再只有通用文件图标。
- 圆形命令按钮增加 80ms 按压反馈；不会延迟实际动作。

### R7：颜色与检查

- 新增 `DocumentStage` 语义色资产；沿用已有系统背景和文字色，不整体换肤。
- 新色由 Material Color Utilities 0.3.0 的 HCT `TonalPalette.fromHueAndChroma(210, 4)` 生成，浅色使用 tone 95 `#eff1f1`，深色使用 tone 20 `#2e3132`。
- 没有新增网络图片、纹理、发光背景或纸张装饰插画；图像均来自实际 PDF。
- 正式构建、截图与行为检查结果见本文验收节，不能用“已改代码”替代验收。

### R8：截图驱动的二次排布

- 第一版 iPad 仍是手机式纵排，第二版改成左侧大页预览、右侧检查清单；普通宽屏展开全部检查。
- 修复主操作动态标题没有走中文本地化的问题。
- 手机显示自动修复项，再折叠通过项，避免所有细节都藏在一个展开入口里。
- 最大辅助字号下主操作过高，压住大量正文；仅将主操作字号上限设为 accessibility1，文件名、检查正文继续响应系统字号。
- 恢复共用翻页控件的 Command-L 页码入口和完整命中区域。

### R9：补齐表单完成度检查

实拍两页演示表单发现：姓名和签名为空，但原检查只报告页面可读、可自动扁平化，仍显示“可以验证”。这说明完成度检查不能只验证文件结构。

- 复用 `PDFFormInspectionService`，检测空白必填项和签名栏；问题带首个相关页码，可回阅读器复核。
- 手写签名沿用现有几何与标记识别，不只判断字符串；不将“有签名外观”称为签名身份或证书有效。
- XFA、外观/计算/脚本问题提示兼容性复核，不宣称完整支持。
- 快速表单检查限制 300 页、5,000 个批注；超预算或检查失败均标为待复核，不自动通过。
- 输出审计把未完成表单的警告加入回执，覆盖扁平化、压缩、脱敏等会重建外观的输出；不是仅加一个 UI 提示。
- 警告不是强制禁止：用户仍可生成明确标为“已检查”的副本；警告保留，不表示表单内容已经完成。
- 预检缓存增加规则版本。旧版本能解码，但不再复用；单文件、批量、磁盘加载三处都校验，不删除 PDF 或回执历史。

### R10：问题先于通过项

- 最终手机截图暴露问题项低于首屏，因此按“阻止、待复核、自动修复、通过”稳定分组。
- 只是展示顺序变化，检查项本身、统计口径和输出验证门禁不变。
- 页面访问不算“已人工验收”，没有伪造阅读完成标记。

## 5. 后续可执行路线

| 批次 | 范围 | 验收方式 |
| --- | --- | --- |
| A：交付闭环 | 导入、签批、检查、分享、重找最终结果；继续减少深层术语 | 10 名目标用户完成三类任务，记录完成率、误分享次数、找回结果耗时；尚未执行 |
| B：稳定性门槛 | 文件发布/索引/回执一致性，失败后可重试 | 按提交前后注入终止、低存储、源修订变更；已提交结果不丢，不发布半文件 |
| C：性能证据 | 100/1,000 页混合 PDF，100/1,000 文件库 | 固定真机、版本、样本、冷/热启动，记录 p50/p95 时间、峰值内存、卡顿；先立基线再定改进目标 |
| D：转换质量 | 合同、发票、表格、中英混排、旋转页 | Microsoft Office 和 iWork 打开，核对前导零、分页、表格、字体回退；明确结构型与保真型产物 |
| E：可复用处理 | 收敛现有批量和处理配方，记录真实结果与失败项 | 20 份混合文件重复运行，停止/继续/重启后不会重复提交或跳过失败 |
| F：发布与付费 | 首次完成路径、商店素材、权限和一次性购买说明 | 首次价值出现前不强推购买；恢复购买、离线使用和历史结果访问都可验收 |

不把每项都做成新按钮。先把已有配方、历史、批量入口接得更顺，再按用户任务失败证据决定是否新增能力。

## 6. 发布表达

推荐表达：“在设备上完成 PDF，保留原件，检查交付副本。”

商店素材优先展示真实任务：

- 合同：填写和签批后检查副本。
- 现场资料：扫描、整理页面、局部复核。
- 日常交付：结果历史里找回具体文件及检查记录。

延续当前一次性购买结构，不在本轮擅自变更商品或价格。商业验证关注“第二次是否还愿意用”，不是只看首次下载。

## 7. 验收

### 构建与有限行为检查

- 五次 Debug arm64 iOS Simulator 构建均成功；包含主 App 和 Share Extension，最终仅有既有 AppIntents 元数据跳过提示。
- `CheckResources.swift`：11 份资源可解析，按文件合计 5,765 个唯一字符串键，无重复。
- `CheckDocumentPreview.mjs`：直接提取生产实现，100 组页数/索引边界通过，包括 Int 极值、空文档、万页文档；任何情况最多九个候选页。
- 新旧缓存 JSON 的实测：新规则接受，缺少规则版本和旧规则版本拒绝复用。
- 新背景和现有前景的八组明暗对比度为 4.99:1–16.24:1，均满足普通文本 AA；不是对整个 App 所有颜色组合的审计。
- 既有租约、源身份与 XLSX 数值/文本分类有限行为检查通过。
- `git diff --check` 通过。没有执行完整 XCTest、UI 测试套件或 sanitizer。

### 真实运行路径

- iPad：选中两页 PDF，点第二张缩略图，纸页确实切换；交付页点第二页并打开预览，阅读器显示第二页及对应检查点。
- iPhone：文档进入交付检查；指定页码输入 999，对两页文档的“前往”禁用。正常页切换与大字号画面已复核。
- 隐藏预览通过进程级参数覆盖现有偏好检查，工作台不显示内容缩略图，缩略带节点为零；不覆盖持久用户设置，不将其写成“已手动点系统设置开关”。
- 三条已有设备诊断在模拟器实际执行：填签并重新打开、脱敏后敏感文本检查、扫描 OCR 后搜索文字重开。
- 填签诊断本轮增加：空字段预检为 review，完成后该提醒转 passed，未完成表单生成的输出回执确实包含 warning。
- 诊断样本耗时分别为 236ms / 54ms / 2637ms，是本次模拟器单次观测，不能声称性能提升百分比或真机基准。

完整截图、JSON 与日志见 [证据索引](../design/document-workbench-2026-09-13/README.md)。

### 环境与未验证事项

- 原工作区包含大量既有未提交变更，本轮没有回退、提交或推送，不把既有全部 diff 计为本轮产出。
- Xcode 正常，系统 `git` 入口指向失效的 MBox wrapper，改用 CommandLineTools 中的 git，没有修改用户工具配置。
- 主机桌面锁定，最初临时 HID 适配尝试两次触发模拟器 `backboardd` 退出。随后改用 AXe 1.8.0，校验发行 SHA-256，临时目录运行；没有 App 崩溃日志。该事件属于验证工具失败，不计为 App 稳定性改善或成功交互。
- 新功能验证使用原有 PaperPath 专用模拟器，未清库，未操作其他项目的模拟器。
- 未验证：真实 Office/iWork 复杂转换互操作、真机扫描/Pencil、长文档峰值内存和能耗、广泛低存储/并发写入故障、完整 VoiceOver 语音与转子。
- 最大辅助字号仍需纵向滚动；颜色、图像和按钮优化不等于整个 App 已达到最终设计质量。深层术语、商店真实用户吸引力和留存仍按后续路线验收。
