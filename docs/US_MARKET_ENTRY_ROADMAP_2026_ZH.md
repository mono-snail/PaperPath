# PaperPath 美区前五路径

更新日期：2026 年 8 月 15 日
执行起点：R191

## 1. 目标定义

“超过第四名或第五名”不能用单一 App Store 榜单定义：

- PDF App 分散在 Productivity、Business 和付费榜。
- 榜单随设备、国家、日期和广告投放变化。
- Apple 不公开真实下载量，第三方收入也只是估算。

PaperPath 使用固定直接竞品组和四项外部指标定义目标。

### 直接竞品组

Adobe Acrobat、PDF Expert、iLovePDF、PDFgear、PDFelement、Smallpdf、
Xodo、Foxit 和 GoodReader。

CamScanner 属于相邻扫描市场，用于判断需求规模，但不纳入 PDF 编辑器排名。

### 12 个月前五标准

以下四项必须同时满足：

| 指标 | 目标 | 原因 |
|---|---:|---|
| 全球 iOS 月下载估算 | >= 40,000 | 高于当前样本中的 PDFelement、Smallpdf、Xodo、Foxit 和 GoodReader |
| 全球 iOS 月消费流水估算 | >= US$40,000 | 高于当前样本第五名约 US$30,000 的量级 |
| 美区 App Store 评分 | >= 4.7 | 专业工具必须先建立结果可信度 |
| 美区有效评分量 | >= 200 | 避免少量种子评价造成虚假高分 |

这些是结果目标，不是发布承诺。任何阶段都不得用内部功能分数替代真实下载、
付费、评分和留存。

## 2. 唯一定位

### 类别

Private, verified PDF workflow for iPhone and iPad.

### 目标用户

需要处理合同、申请表、税务、医疗、身份证明、学校和工作文件，但不希望把
PDF 上传给在线服务的个人与专业用户。

### 用户任务

> 把这份重要 PDF 填完、签好、整理或脱敏，然后确认最终副本没有发错。

### 用户最怕的失败

1. 敏感内容被上传或收集。
2. 原件被覆盖，无法恢复。
3. 脱敏只是视觉遮挡，底层文字仍可复制。
4. 签名、表单、批注或页面在导出后丢失。
5. 多份文件中有一份失败，却被统一“成功”提示掩盖。

### 产品承诺

> Finish important PDFs privately, then verify the copy before you share it.

中文内部口径：

> 私密完成重要 PDF，并在分享前验证最终副本。

### 四个证明

1. PDF 内容没有 App 自建上传路径。
2. 默认使用私有工作副本，原文件不被静默覆盖。
3. 完成后重新打开和逐页检查输出，而不是只判断写入成功。
4. 保存 Receipt、文件指纹、源文件血缘和失效状态。

### 明确不争夺

- 不宣传功能最多。
- 不与 PDFgear 竞争免费工具数量。
- 不与 Acrobat 竞争企业生态和跨平台协作。
- 不为追逐 AI 标签上传用户 PDF。
- 不在没有成熟引擎时承诺任意复杂版式编辑。

## 3. 增长模型

PaperPath 的增长链路必须成立：

```text
高意图搜索
    -> 商店页理解“本地 + 验证”
    -> 免费完成一次真实结果
    -> 第二次重要任务产生付费
    -> 稳定结果触发评分
    -> 评分和关键词排名带来更多自然下载
```

### 收入目标的可行性

长期买断价按 US$19.99 计算：

- US$40,000 月流水约需要 2,000 次月购买。
- 付费转化率达到 5% 时，需要约 40,000 月下载。
- 因此“4 万下载 + 4 万美元流水”是同一套模型，不是两个孤立目标。

首发 US$9.99 只用于降低第一批用户的决策成本，不作为长期价格。

### 外部北极星

`Monthly verified customers`

| 50 页常规 PDF 的验证流程 | 不阻塞主线程，可取消，可恢复 |

| 阶段 | 90 天目标 | 12 个月目标 |
|---|---:|---:|
| 首次打开后导入或扫描 | >= 45% | >= 55% |

## 5. 三条黄金路径

### A. Fill, sign, verify

```text
Import
  -> 检出表单或签名需求
  -> Fill / Sign
  -> 显示剩余未完成项
  -> Verify & Share
  -> 打开最终副本和 Receipt
```

验收：

- 首次用户不需要理解 PDF 专业术语。
- 完成签名后只有一个明确下一步。
- 最终副本重新打开后，表单、签名和页数均通过检查。

### B. Redact, verify

```text
Import
  -> Hide private info
  -> 永久脱敏
  -> Verify & Share
  -> 验证文字层、批注和元数据
```

验收：

- 明确区分视觉遮挡和永久脱敏。
- 脱敏后不可搜索、复制或恢复被移除内容。
- 原件保留，输出独立命名。

### C. Scan, OCR, verify

```text
Scan
  -> Enhance
  -> OCR language and custom words
  -> Review low-confidence pages
  -> Searchable copy
  -> Verify & Share
```

验收：

- 相机、旋转、低光和多页在真机通过。
- OCR 失败或取消不覆盖旧结果。
- 输出在 Files、Preview、Acrobat 和 PDF Expert 中可正常打开。

## 6. 分阶段迭代

### R191：定位统一

目标：让首次看到 App 的用户在首屏和核心任务中理解差异。

- 副标题改为 `Private PDFs. Verified output.`。
- 用户可见的 `Safe Share` 改为 `Verify & Share` / `Verified Copy`。
- App Store 元数据、README 和开发准则使用同一定位。
- 内部 `safeShare` 枚举、持久化值和文件兼容性不改名。

完成标准：

- 首屏仍保持当前 106pt 左右横向 Hero 和信息密度。
- 普通字号与 Accessibility XXXL 不截断。
- UI 测试锁定新的品牌副标题。

### R192–R194：黄金路径收口

目标：三条黄金路径都能在一到两个清晰层级内完成。

- 对表单、签名、脱敏、OCR 的下一步统一指向 Verify & Share。
- Verified Output 页面先解释结果，再展示 SHA-256 等技术证明。
- 第二次打开 App 可恢复未完成任务和证据页。
- 为不兼容 PDF 提供事实、原因和可靠替代路径。

完成标准：

- 三条路径各有真实 PDF 样本、单元测试和 UI 流程。
- 不增加新的通用工具入口。
- 从任务完成到 Verified Output 不超过一个额外决策页面。

### R195–R202：严格全能力超越

目标：先把用户可感知的专业功能补全，将严格全能力分从 R194 的约
`9.2` 提升到至少 `9.5`，超过当前 PDF Expert 基线 `9.4`；在达到该门槛前，
真机协议排障、商业化和商店投放不得抢占主开发线。

按高权重缺口执行：

1. R195：本地 PDF 到 PowerPoint。生成真实 `.pptx`，每页一张高保真幻灯片，
   原文字层或本地 OCR 作为可搜索层，不上传文件。
2. R196：图片对象兼容面。安全导出 DCT、Flate、软蒙版和 Form XObject 中可
   解码资源；明确区分原始字节、无损解码和重编码结果。
3. R197：图片编辑兼容面。支持复用对象、xref stream 和常见透明图片的独立
   副本替换；无法证明局部替换安全时继续阻断。
4. R198：长文阅读提升。增加本地语义重排、连续页、页位锚点、字体/字号/
   段宽、跨页朗读和语速控制，保持原 PDF 视觉阅读入口。
5. R199：扫描与 OCR 专业度。低置信度页自动使用高分辨率文档增强二次识别，
   增加双栏顺序、增强通道归因和逐行人工纠错；修正同步进入搜索、摘要、
   Focus Reader 与可搜索副本。
6. R200：权限与表单深度。补齐独立 owner key 与打印/复制/批注/填表/页面
   管理权限；计算字段和格式校验继续推进；
   数字证书保持检查与状态展示，不伪造签名引擎。
7. R201：批注与页面专业度。补齐 Pencil 快捷动作、页面标签、附件提取及常见
   审阅对象；不把低兼容音频批注强塞进 Verified Output。
8. R202：格式与编辑收口。补齐 PPTX 异常版式、跨页编辑边界和 Office 输出
   互操作问题，重新计算 11 项严格加权分。

完成标准：

- 每项必须是用户可完成的真实功能，不得用空入口或改扩展名凑数。
- 每项有正常、异常、取消和大文件边界；输出重新打开并核对包结构或 PDF 结构。
- 严格加权分以当前代码和真实样本证据计算，达到 `>= 9.5` 才进入下一阶段。
- “本地可信交付”领先继续保持，不为补功能引入 PDF 上传或账号依赖。

### R203–R206：发布与商业门禁

目标：功能达到领先线后，再把它升级为可发布、可收费的产品。

- 当前仅允许使用 iOS Simulator；未经用户再次明确授权，不得连接、安装、
  启动或测试任何物理 iPhone / iPad。真机项目保留为待办，不阻塞当前功能线。
- VisionKit 相机、Apple Pencil、锁屏保护和真实 iCloud 账号真机门禁。
- iPhone 小屏、Pro Max、iPad 分屏、外接键盘和 Accessibility XXXL。
- Acrobat、PDF Expert、Preview、Files 和 Windows 阅读器交叉打开。
- StoreKit 2 永久解锁；Free 包含一次真实 Verified Output。
- 购买恢复、家庭共享、退款状态和离线权益缓存。

完成标准：

- 所有 P0 问题归零，无主线程长时间阻塞。
- 真机证据与模拟器证据严格分开。
- 购买、取消、失败、恢复、退款和无网络状态均可恢复。
- App Store 文案与实际解锁范围一致。

### R207–R210：商店获客与反馈

目标：按用户任务建立入口，不靠“all-in-one”同质化关键词。

建立三个商店产品页：

1. `Offline PDF editor`：本地处理、无账号、原件保留。
2. `Sign and send PDF`：填写、签名、验证最终副本。
3. `Redact PDF privately`：永久脱敏、元数据清理、重新检查。

关键词方向：

`offline,editor,redact,sign,scanner,ocr,forms,merge,compress,privacy,local`

完成标准：

- 前三张截图只表达隐私、完成任务和输出验证。
- 不用内部评分、夸张排名或无法证明的安全承诺。
- 先验证自然页转化，再决定是否投放 Apple Search Ads。

首发后用真实失败和用户行为决定下一轮：

- 第二次成功生成 Verified Output 后才允许系统评分提示。
- 最近发生失败、取消或数据恢复时不请求评分。
- 每周只处理前三类高频任务失败和前三类流失原因。
- 公开更新节奏保持稳定，但不为周更牺牲兼容性。

90 天门槛：

- >= 5,000 月下载。
- >= US$5,000 月流水。
- >= 50 个美区评分且平均 >= 4.7。
- P0 用户数据问题为 0。

### R211–R214：前五扩张

只有前三条黄金路径的数据达到门槛后，按顺序扩展：

1. Share Extension：从 Mail、Files 和浏览器直接进入私有工作副本。
2. 英语、西班牙语和简体中文界面本地化。
3. 可复用批量配方，但每份文件继续独立预检和失败归属。
4. 更强的兼容编辑子集，仍保持不兼容即阻断。

暂不优先：

- 在线 AI 问答。
- 团队协作和自建云盘。
- 工程测量、复杂图层和数字证书。
- 与可信交付无关的装饰性首页模块。

## 8. 每轮执行规则

每个 Round 必须按以下顺序：

1. 指定一个用户任务或一个真实失败。
2. 记录当前路径、证据和可测验收标准。
3. 只修改完成该目标所需的最小产品边界。
4. 完成构建、定向测试、回归和必要真机验证。
5. 更新迭代记录，并明确仍未验证的部分。

不得：

- 为提高内部评分增加低价值功能。
- 用测试数量替代用户结果。
- 在没有真实用户数据前宣布市场领先。
- 为排名引入跟踪 SDK、上传 PDF 或破坏本地优先架构。
