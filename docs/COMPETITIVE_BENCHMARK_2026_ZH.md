# PaperPath 2026 同类产品基准

更新日期：2026 年 8 月 22 日

## 1. 对标结论

PaperPath 的直接对手不是 Acrobat 企业套件，而是用户会在 iPhone / iPad
上同时考虑的四类产品：

- PDF Expert：Apple 平台专业编辑与原生体验标杆。
- PDFgear：免费、功能密度高的全能型移动 PDF 工具。
- Xodo Mobile：跨端、批处理和工具覆盖广的效率型产品。
- Smallpdf Mobile：扫描、转换和 Web / 移动衔接成熟的服务型产品。

PaperPath 不以 Office 转换、任意原文编辑、云同步数量取胜。它必须在一个
更窄但完整的场景中成为第一选择：

> 在设备本地完成一份或一组 PDF，发现遗漏，生成独立副本，并确认这些副本
> 可以放心交付。

### 我们应当突出、但不能夸大的四个优势

1. **可信交付闭环**：预检、创建、重开、审计、指纹、Receipt、分享是同一条路径。
2. **源文件和隐私安全**：无账号、默认本地处理、私有工作副本、源文件不覆盖。
3. **建议可解释**：文档类型和下一步都带置信度与证据页，用户可以回到原文判断。
4. **批量错误可归属**：每份文件拥有独立阶段、稳定短码、错误时间线和定向恢复动作，而不是整批只返回一个错误。

PaperPath 不宣称功能总量超过 PDF Expert、Xodo 或 Smallpdf。真正可防守的优势是：

> 同类产品帮助用户“处理 PDF”，PaperPath 进一步帮助用户证明“这份输出就是
> 刚刚检查过、可以交付的那一份”。

## 7. AI 感审计

当前应删除或收敛的模式：

1. 四个等尺寸、等权重、同构造的首页任务卡。
2. 工具面板中“卡片套卡片”的连续纸面容器。
3. 用彩色图标底板代替真实文档状态和结果预览。
4. 把 PDF 阅读器放进带圆角和阴影的预览框，削弱原生工作区感。
5. 每个页面都重复大标题、说明文字和功能介绍。

必须保留并放大的设计资产：

1. 真实 PDF 首页缩略图。
2. 纸张、装订夹、印章、红线和扫描光束等领域视觉。
3. Serif 文档标题与 SF Pro 操作文字的对比。
4. 系统 Sheet、Menu、Share Sheet、文件选择器和原生触觉反馈。
5. 深浅色下独立校准的纸张层级，而不是简单反色。

## 10. R70 批量能力复评

| 评分 | R60 | R70 | 提升依据 |
|---|---:|---:|---|
| 产品价值 | 9.2 | **9.3** | 批量结果可恢复，不因一次停止或局部失败丢失已验证成果 |
| 功能专业度 | 9.0 | **9.2** | Source、Preflight、Create、Verify、Save、Stopped 六阶段归属到具体文件 |
| 技术能力 | 9.0 | **9.3** | 内容版本缓存、最多两路预检、单路重型输出、逐页 autoreleasepool |
| 交互与设计 | 9.1 | **9.2** | 第二页移除 AI 式推荐卡；错误行提供短码、原因、恢复建议和定向重试 |

批量性能策略：

- 未变化文件的预检结果按 `contentRevisionID` 复用。
- 轻量预检最多同时处理两份，避免大量文件完全串行等待。
- 栅格化、输出审计和保存仍保持单文件顺序执行，控制 PDFKit 与图片内存峰值。
- 页面缩略图检查在逐页 `autoreleasepool` 内释放临时图像。
- Retry 只处理 FAILED / STOPPED 文件，VERIFIED 输出不会再次生成。

错误归属策略：

| 阶段 | 短码示例 | 用户看到的处理 |
|---|---|---|
| Source | `S-001` | 重新导入缺失源文件 |
| Preflight | `P-101` / `P-201` / `P-202` | 重试检查、解除阻断或打开证据页 |
| Create | `C-101` | 释放内存或存储后只重试该文件 |
| Verify | `V-201` | 回看源页面，避免分享未通过审计的输出 |
| Save | `S-301` | 释放存储后重试保存 |
| Stopped | `B-001` | 恢复未完成文件，保留已经 VERIFIED 的结果 |

实际模拟器路径使用三份内置 PDF 完成一次批量处理，结果为三份独立 VERIFIED
输出，队列正常收敛。该验证不替代后续大文件与异常样本压力测试。

## 13. 仍然存在的差距

| 差距 | 领先产品 | 影响 | 决策 |
|---|---|---|---|
| 原文、图片和链接直接编辑 | PDF Expert、PDFgear、Xodo | 功能总量和临时纠错能力较弱 | **暂不补**；需要独立版式引擎，低质量实现会破坏文档 |
| Apple Pencil 高级注释、音频批注 | PDF Expert | 重度学习、施工图和课堂笔记用户不够强 | 后续补工具预设与落点精度，不把音频混入交付主线 |
| 多标签、图层、测量与工程图 | Xodo、PDF Expert | AEC 专业场景无法覆盖 | **不进入当前定位** |
| Office 双向转换与 AI 聊天 | 四个竞品 | 搜索流量和功能数量较弱 | 保持不参赛；通常依赖上传或服务端 |
| 多语言界面 | 四个竞品 | 海外分发和转化受限 | 发布前优先补简中、繁中、日语和西语 |
| 500–1,000 页真机压力数据 | 暂无可比公开数据 | 仍不能证明极端文件下的峰值内存 | 后续建立真机样本集，记录峰值内存、耗时和取消延迟 |
| 签名任意落点与精细缩放 | PDF Expert、Xodo | 固定左中右位置不适合复杂签名栏 | 下一阶段优先补拖拽落点和边界吸附 |

结论：PaperPath 已经没有“可信交付主线缺功能”的明显短板。剩余差距主要是
重型编辑、工程图和全球化，不应为了表格全满而破坏产品边界。最值得继续补的
是签名落点精度、多语言和真机大文件证据。
