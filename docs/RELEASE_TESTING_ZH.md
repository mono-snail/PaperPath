# PaperPath 发布测试

## 一键自动化

需要 Xcode、iOS Simulator、Python 3 和 Node.js。不需要先安装 XcodeGen；使用仓库中的工程。
先读取 `~/.codex/simulators/pool.json` 并运行全局 guard 状态检查。PaperPath iPhone 固定复用 `2A313B9A-7363-4AE1-ADFB-2CDF0F680653`；iPad 只在明确需要兼容检查时，单独复用 `FCC639C3-8DDF-4C6D-966E-773238C82805`。每次只选一种设备：

```bash
python3 tools/RunReleaseChecks.py --family iphone --node <Node可执行文件绝对路径>
```

脚本自动通过全局 `guard.py run` 持有完整前台会话锁，串行执行工具自检、功能契约、单测、覆盖率和所选设备的 UI，再做通用 iOS Release 编译。iPad 需另外明确运行 `--family ipad`；单次结果仅代表所选设备类型。旧的同时传入 `--iphone` 和 `--ipad` 命令会在运行前拒绝。所有 XCTest 指定唯一登记 UDID、关闭并行，并限制一个目的地、一个 worker。设备忙、缺失或不兼容时停止，不创建替代设备。

不会创建、克隆、擦除、重置或删除模拟器，不自动下载运行时或模型。仅关停本轮启动的设备并保留数据；运行期间不要修改源码或使用测试中的模拟器。
每阶段的命令、日志、测试结果树、失败信息、覆盖率以及 `.xcresult` 位于 `.artifacts/release-时间戳/`；截图与生成的文档附在结果包中，可以在 Xcode 打开。失败阶段不会阻止后续阶段收集证据。不会自动重试来掩盖不稳定测试。客服深色测试单独串行运行，先读取并设置模拟器的实际深色外观，结束后恢复原外观；只传测试名称或启动参数不能作为深色证据。

默认保留 XCTest 日志和失败现场，不额外采集完整模拟器系统诊断；Xcode 的这一步可能等待十分钟。需要调查模拟器或系统故障时，加 `--system-diagnostics` 启用。该选项不影响失败判定和测试覆盖。

`report.json` 绑定 Git 提交和工作区内容指纹；源码在运行中改变时，整轮检查判失败。退出码非零代表失败或中断。允许的单测跳过只有模拟器不支持的 `testStoreAppliesCompleteFileProtection`，必须在真机补验。Quick Look 服务不可用等其他跳过会阻止自动化通过。

门禁将实际执行的测试名称与源码清单逐一对照，防止 scheme 过滤测试后显示绿色。已移除 StoreKit 内购测试，付费下载入口检查随普通 UI 套件运行。iPad 专属检查器测试只在 iPad 轮次运行且必须通过。

## 发布判定

`AUTOMATION_PASSED_MANUAL_REQUIRED` 只表示当前源码的自动化通过。`FAILED` 或 `INTERRUPTED` 不允许按自动化通过处理。

以下项目需要针对候选发布版本记录设备、系统、构建号、操作、结果与附件；没有证据就保留待验证：

- 真机相机：首次授权、拒绝后恢复、多页拍摄、重拍、低光、旋转与高清图片内存。
- 真机安全：文件保护属性、锁定与后台预览、生物识别失败与取消、分享扩展从 Files/其他 App 接收文件。
- 分发安装：App Store/TestFlight 安装、离线处理及重复/批量输出；无应用内购买流程。
- iCloud：真实账号在两台设备同步轻量元数据、离线恢复、冲突合并和删除；确认 PDF 与提取文本没有被同步。
- 支持系统：最低 iOS 17 与当前支持版本，iPhone 和 iPad；模拟器中安装了哪个版本，不等于已经验证所有支持版本。
- 长文档与兼容性：大扫描件内存、取消、OCR 质量；目标阅读器/Office 中打开输出文件并检查页面、文字、表单和批注。
- 分发准备：签名归档、隐私声明、支持与隐私链接、商品配置和 App Store 提交信息。

自动化通过且这些项目全部有通过证据后，才可将候选版本标记为发布就绪。自动化不保证不存在任何缺陷；它提供可重复的验证与明确的阻断条件。

```bash

```

新增五条 `testMergeCorpus…` 用例，连同原有合并/拖动排序旅程共六条 UI 流程；另有合并、拆分便签批注尺寸保留两条服务回归，共八项 XCTest。每次在独立文档目录中准备七份 PDF：六份程序生成素材（1/2/1/3/1/2 页，含横版、旋转页、批注和长文件名），一份缓存的真实 JBIG2 扫描 PDF。运行不访问网络；缓存缺失会失败，不自动下载或用合成样本替代。仅清理本轮独立测试目录中的数据，保留普通文档库和模拟器数据。

覆盖连续添加到第七份、清空后反向添加、删除后从两份降到一份再添加、取消重进、搜索无结果、仅添加匹配文件、大字号和合并后重启重开。辅助函数可以滚动，但禁止通过重新展开文档库来补救选择后意外折叠；每次添加前后均断言展开状态。

完整专项运行后，`AuditMergeOutputs.py` 使用独立的 pypdf 读取界面实际保存的文件，检查七份原件字节未改、无重复输出、十一页的源文件顺序、文字、页尺寸/裁剪/旋转、批注文字及矩形，并用已有 Poppler 在 1440px 尺度逐页渲染，要求像素完全一致。PDFKit 可能把 JBIG2 转码为 Flate；编码变化会记录，不能单凭压缩编码不同认定内容变化，仍必须通过逐页像素比较。运行不安装或下载解码器；固定素材的渲染一致性不等于所有真实文件都已覆盖。`test_merge_output_audit.py` 通过故意错误的页序、缺页、原件修改和证据缺失，验证校验程序会拒绝错误。

原始日志、xcresult、素材附件、源码前后指纹、`independent-merge-audit.json` 和 `merge-report.json` 保存在 `.artifacts/compression-qa-时间戳/`，可用 `--output` 指定独立目录。失败、跳过、漏跑或运行期间源码变化均不能判为通过。`--test` 仅用于定向诊断，报告明确标注范围，不冒充完整八项回归及输出验收。已有真实 PDF 发布脚本的 `--ui` 模式也纳入新增五条流程。
