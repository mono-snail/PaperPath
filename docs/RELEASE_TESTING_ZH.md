# PaperPath 发布测试

## 一键自动化

需要 Xcode、iOS Simulator、Python 3 和 Node.js。不需要先安装 XcodeGen；使用仓库中的工程。
先用 `xcrun simctl list devices available` 找到 iPhone 和 iPad 的 UDID，再运行：

```bash
python3 tools/RunReleaseChecks.py \
  --iphone <iPhone模拟器UDID> \
  --ipad <iPad模拟器UDID> \
  --node <Node可执行文件绝对路径>
```

脚本运行门禁自身测试、功能覆盖契约、全部单测、代码覆盖率，再按完整名单分批并行运行 iPhone/iPad UI，最后执行独立 StoreKit 购买测试与 Release 构建。默认每种设备两个独立 UI 进程；机器资源紧张时加 `--ui-workers 1`。额外的两个临时模拟器由脚本创建，逐台确认启动完成，测试后自动清理。运行期间不要修改源码或同时使用测试中的模拟器。
每阶段的命令、日志、测试结果树、失败信息、覆盖率以及 `.xcresult` 位于 `.artifacts/release-时间戳/`；截图与生成的文档附在结果包中，可以在 Xcode 打开。失败阶段不会阻止后续阶段收集证据。不会自动重试来掩盖不稳定测试。

默认保留 XCTest 日志和失败现场，不额外采集完整模拟器系统诊断；Xcode 的这一步可能等待十分钟。需要调查模拟器或系统故障时，加 `--system-diagnostics` 启用。该选项不影响失败判定和测试覆盖。

`report.json` 绑定 Git 提交和工作区内容指纹；源码在运行中改变时，整轮检查判失败。退出码非零代表失败或中断。允许的单测跳过只有模拟器不支持的 `testStoreAppliesCompleteFileProtection`，必须在真机补验。Quick Look 服务不可用等其他跳过会阻止自动化通过。

门禁将实际执行的测试名称与源码清单逐一对照，防止 scheme 过滤测试后显示绿色。普通 UI 轮次排除的三个购买测试必须在 `PaperPathCommerce` 中全部运行，不能将跳过算作通过。iPad 专属检查器测试只在 iPad 轮次运行且必须通过。

## 覆盖内容

| 层级 | 内容与证据 |
| --- | --- |
| 功能契约 | `AUTOMATION_COVERAGE.json` 维护 14 个快捷任务、24 个文档工具、隐私扫描流程的逻辑测试与独立 UI 旅程归属；新增枚举功能没有归属会失败 |
| PDF 核心 | 导入、扫描渲染、合并拆分、排序裁剪、批注、表单、签名、遮盖、加密、压缩、OCR、Office 导出、可信输出、收据与验签 |
| 数据安全 | 原件隔离、失败回滚、并发互斥、磁盘不足、取消恢复、损坏输入、路径越界、篡改、备份排除、私有文件生命周期 |
| 发布体验 | 评分门槛与失败抑制、损坏的计数与日期、用户设置、预览预算、诊断包字段及清理、锁屏可访问性边界 |
| UI | 实际操作结果、取消再进入、状态隔离、进程存活、搜索与历史、OCR、工具切换、任务恢复、中英文及大字布局 |
| 购买 | 待批准与重新检查、批准后解锁、无购买恢复、购买后杀进程重启、退款撤权及再次重启 |

代码覆盖率沿用 `CheckCodeCoverage.mjs` 的门槛：服务与领域聚合均至少 80%，发布核心服务每个至少 65%，PDF 检查至少 85%，分享扩展至少 55%。覆盖率表示代码被执行；仍必须同时满足测试结果与真实输出断言。

## 发布判定

`AUTOMATION_PASSED_MANUAL_REQUIRED` 只表示当前源码的自动化通过。`FAILED` 或 `INTERRUPTED` 不允许按自动化通过处理。

以下项目需要针对候选发布版本记录设备、系统、构建号、操作、结果与附件；没有证据就保留待验证：

- 真机相机：首次授权、拒绝后恢复、多页拍摄、重拍、低光、旋转与高清图片内存。
- 真机安全：文件保护属性、锁定与后台预览、生物识别失败与取消、分享扩展从 Files/其他 App 接收文件。
- 分发购买：Sandbox/TestFlight 的真实购买、恢复、待批准、退款同步；本地 StoreKit 结果不能代替分发环境。
- iCloud：真实账号在两台设备同步轻量元数据、离线恢复、冲突合并和删除；确认 PDF 与提取文本没有被同步。
- 支持系统：最低 iOS 17 与当前支持版本，iPhone 和 iPad；模拟器中安装了哪个版本，不等于已经验证所有支持版本。
- 长文档与兼容性：大扫描件内存、取消、OCR 质量；目标阅读器/Office 中打开输出文件并检查页面、文字、表单和批注。
- 分发准备：签名归档、隐私声明、支持与隐私链接、商品配置和 App Store 提交信息。

自动化通过且这些项目全部有通过证据后，才可将候选版本标记为发布就绪。自动化不保证不存在任何缺陷；它提供可重复的验证与明确的阻断条件。
