## 功能与视觉背景

面向处理发票、合同和扫描文件的人，任务是本地完成 PDF 操作、保留原件并检查结果。保留导入、扫描、合并、拆分、压缩、Vision OCR、阅读批注、表单签名、隐私处理、转换和可信输出能力。不引入 AI 聊天、协作、云盘、虚构用量或新定价。

原有纸白、深蓝和文档缩略图可以延续；品质主要来自标题层级、排版、对齐和任务布局，而不是插画、阴影或装饰。真实参考的来源和角色详见完整提示词。最终生产控件应由 SwiftUI/PDFKit 绘制。

## 我的取舍与实施约束

1. 首页：收紧品牌标题与工具区域，让近期文档成为主要内容；普通字号可探索四项横排，小屏、长翻译和大字号应两列或单列，不压缩字号和点击范围。
2. 合并：选中顺序优先于可选文件；将文件库作为次级展开区域或选择器。输出名、原件保留说明与主操作保持可达。图中第二轮仍画成展开列表，不能当作折叠状态的准确示范。
3. 压缩：保留三档、采样预估和图像化副本的损失提醒。图示处于检查中，因此没有编造输出大小或节省比例。精确的禁用条件以现有逻辑为准。
4. iPad：阅读模式应优先保障纸张宽度。右侧工具栏可按需展开；较窄设备使用浮层或工具选择器，不强制三栏。
5. 生成图并非像素规格：仍有轻微渐变残留、个别图标漂移、压缩选项宽度和文字对比等细节。结果页应保留现有结果语义图标，不能照搬第二轮的柱状图符号。iPad 的页码导航在单页时须正确禁用。工具需保持现有兼容性规则，不代表当前发票真的含表单或需要 OCR。

静态图可以判断构图与视觉层级，无法证明拖动、键盘遮挡、VoiceOver、深色、Dynamic Type 或处理状态交互正确。这些需在实现后用真实运行画面和行为验证。
